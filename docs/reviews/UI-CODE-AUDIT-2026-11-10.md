# 2026-11-10：布局检查与界面更新优化

本次以现有 Material 3 Expressive 和宋体/Charter 为依据，检查实验台在 1440、960、390、320 像素宽度的实际布局、五/六图组合、侧栏、图位工具栏与响应式切换。没有重做视觉风格、增加菜单按钮或改变天文公式。

## 已修复问题

1. **五/六图缺少三行定义。** 原网格只有一至四图的显式行定义，后续图位采用隐式行，平板上第三行会被挤压、裁切。现在宽屏明确使用三行，每行至少240像素；空间不足时在绘图区滚动，保留时间条和侧栏。三行布局不显示只适用于两行的水平分隔手柄，行比例字段同时禁用。手机仍使用原来的单图标签切换。
2. **界面在值不变时仍重复写入DOM。** 页面路由、图内编辑入口、侧栏和视角同步反复设置hidden、文字、ARIA及disabled。现在比较值后才提交，复用一次同步中的图位快照与成员集合，减少重复数组复制。没有增加全局轮询或缓存科学结果。
3. **视角选择器范围过宽。** 原`[data-view]`选择器还会选中画布和编辑容器。现在只同步`button[data-view]`，避免给非按钮附加pressed语义。
4. **画布可见性缓存失效。** 图位从隐藏变为显示或被重排后，旧IntersectionObserver结果可能仍为false，出现可见图框内空白。现在仅使受影响画布的可见性缓存失效，并由原有同一个观察器重新观察；不会为每一帧新建观察器。回归不只检查图框尺寸，还检查展开及滚动后的实际绘制像素。

## 测量边界

在相同观测状态下同步调用`renderUIWorkspace()`十次，使用MutationObserver记录body内的属性、文字与子节点写入：

| 宽度 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1440 | 740 | 0 |
| 960 | 740 | 0 |
| 390 | 460 | 0 |
| 320 | 460 | 0 |

这里的“0”仅指该同步函数在值未变化时的DOM写入，不是整站没有更新，也不是播放时不更新。没有据此宣称整站FPS或加载速度提升某个倍数。时长测量受模型准备与软件渲染负载影响，不作为严格对照结论。最终布局采样隔离了后台搜索Worker，功能回归仍使用原应用入口。

## 验证与维护

- `workspace-rendering.cjs`：五/六图三行、最小画布高度、最后一行可达、分隔手柄、绘制像素、稳定DOM、按钮ARIA、天体切换及手机布局。
- `layout-invariants.cjs`：原字体、滑条和字段分离、触控按钮、字段对齐、控件不重叠与无横向页面溢出。
- 全仓库源码解析、生成一致性与按变更范围选择的发布回归由CI继续执行。

浏览器检查使用Chromium及软件渲染；未将其表述为真实Safari或所有GPU的兼容性认证。数值模型、存档协议、分享编码和已有网址保持兼容。
