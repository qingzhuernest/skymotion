# SkyMotion — Material 3 Expressive

## Design authority
The interface follows Material 3 Expressive. The user authorizes replacement of the previous visual system, retaining the existing fonts. Scientific behavior, real content and accessible interaction remain intact. This document supersedes earlier appearance notes; no Impeccable aesthetic rules apply.

## Typography
Chinese: self-hosted SkyMotion Reading, Songti SC / SimSun fallback. English: self-hosted SkyMotion Charter, Charter / Georgia fallback. Use the same face for labels, controls, reading and headings. Tabular numerals for measurement and time. Preserve language switching and the complete scientific annotation set.

## Color roles
ui-palette.css owns literal colors. Primary #255c43, on-primary white; primary-container #c4d5c6, on-container #103b25. Secondary #51634e, secondary-container #ccd9c7. Tertiary #73512c, tertiary-container #ffdfb4. Background #e2e9de; surface #e9efe5; containers #dfe8da / #d6e1d0 / #cddbc6 / #c5d5bd. Ink #19251c; supporting text #4d5d4d. Large light surfaces use muted sage tones to reduce glare against observation canvases. on-primary white is a foreground role, never a panel background. Scientific canvases keep their independent dark palette and series meaning. Immersive mode remaps all surface levels and text roles together.

## Components and density
- Global top app bar: one shared identity/navigation layout for Lab,3D and documents, stable primary destinations, direct Sun/Moon connected choice where applicable, customization and language. The3D toolbar groups display choices separately from matching outlined auxiliary actions. 64px desktop minimum. On phones, a compact identity precedes the full, wrapping primary navigation; Sun/Moon and customization occupy a separate lower action row. Navigation never requires horizontal scrolling.
- Navigation: primary destination indicators use a short primary underline. Connected exclusive controls use a 2px gap, 12px inner corners, outer corners capped at half the target height, and a fully rounded selected segment; press morphs to 16px. Native navigation keeps its shape/color indicators. Official filter chips use their built-in selected checkmark and accessible pressed state; no second moving selection backplate is added.
- Sidebar: one shared menu-section implementation for content, settings and3D explanations, including the same expansion icon, heading and body spacing. White 20px grouped surfaces on a tonal rail; nested groups use 16px corners. Inner heading radius subtracts the 1px structural stroke so background never covers the outline. List rows share alignment, primary selection and overlay state layers; remembered sky orientation is not selected while another diagram is current. Rails and their sticky collapse headers are owned by interface-motion.css for both Lab and3D. Seasonal and planet choices share a compact grid:32px painted surfaces with fully rounded ends inside40/48px targets. Lower height gives wide, flat proportions; selection changes fill.
- Buttons: filled primary, filled tonal, outlined, text and icon roles. Small desktop targets at least40px; narrow or coarse-pointer targets48px. Visual density must not reduce target size. Explicit focus, disabled, hover and pressed states.
- Fields: Material outlined fields, visible labels, native editing and keyboard support. Switches use the shared52×32 track and selected thumb geometry; checkboxes remain distinct controls.
- Sliders: settings use official md-slider; scientific parameters retain native range inputs with16px tonal tracks, active fill,4px upright handles and gaps. material-controls.js owns progress presentation, never model values. State owners update presentation after programmatic changes, including playback, history and dynamic parameter editors. No polling loop or patched native value setter.
- Observer view: the ground compass shares observerFrame with the sky. Forward world directions project onto the far (upper) half of the ground; horizontal motion matches the sky. The observer and forward arrow stay fixed. Compact panes keep horizon bearings and omit redundant compass labels.
- Narrow comparison cards: at420px or less, the chooser and drag handle occupy the first row; pane actions occupy a separate row. Chooser captions stay on one line and retain their complete accessible name. Object editing separates primary actions from help and history so headings and action labels keep usable width.
- Surfaces:28px outer containers,20px grouped sections,16px inner cards,48px reserved for expressive large surfaces. Elevation belongs to floating menus and sheets; persistent surfaces use tonal separation. Compact2×2 readouts and compact playback preserve observation space.
- Reading: grouped entry list, shared colors and shapes, stable table width and chapter hierarchy. A quiet reading surface with always-visible contents, one header divider and a localized Back to top action. Document category links reuse the connected-choice component with native navigation semantics and aria-current; Markdown download uses the shared outlined action. Opening questions and answers share one left edge and keep their timed dialogue.
- Welcome: existing interactive star field and opening behavior, larger retained-font title and56px main action. No additional opening buttons.

## Motion and accessibility
Shared state layers and350ms expressive shape transitions; short150ms color feedback, shorter press response. Existing panel and disclosure springs remain bounded and reversible. Canvas coordinates never scale as UI feedback. Respect reduced motion, keyboard focus, screen-reader names and native input semantics. Responsive composition must work at320/390/960/1440px in both languages.

## Ownership
ui-palette.css defines color; design-system.css defines shared component tokens and skins; route CSS owns placement. Google @material/web 2.5.0 provides the shared selects, selection chips, settings sliders, switches and settings action buttons. material-controls.js adapts native select values/events to those official elements without patching browser prototypes; preferences.js owns settings values. Scientific sliders and navigation keep their existing native controls. The pinned, locally bundled entry is scripts/material-web/source.js; rebuild with npm ci --prefix scripts/material-web and npm run build --prefix scripts/material-web. interface-motion.css owns parameter rails, sticky headers and collapse/expand controls. workbench-menu.css owns the single navigation-row implementation. interface-motion.js handles reversible presentation transitions and installs shared choice classes. diagram-reference-store.js owns reference IDs, creation, duplication, drafts, saves and history; diagram-reference-renderer.js owns read-only drawing, label layout and hit geometry; diagram-tools.js owns editing and coordinates those two modules. Shared navigation, page links and view-choice skins live in design-system.css, including their responsive rules. Properties place scientific parameters before the separate Name and annotation group. Route CSS does not override these component skins. Application state and astronomy remain framework-independent.

## Programmatic control values
State owners commit native field values through `SkyMaterial.setValue(control, value)`; callers that directly change selection can use `syncChoices(select)`. These calls update presentation without generating input/change events. The shared library loads once, before page controllers. Native select/option prototypes remain unchanged; DOM observation handles added, moved and relabeled controls.
