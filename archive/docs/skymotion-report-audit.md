# 对《skymotion_bug_report_and_fixes》的核查

**后续状态（2026-10-06）：BUG-02、05、11、14、08 已在后续修正版修复；下文是修复前的审计结果，不代表新包仍有这些缺陷。**

核查日期：2026-10-06。范围：当前交付版本 `/workspace/sunlab/dist`。通过公开地址读取的 page-navigation.js、app.js、moon.js、motion.js、time-workbench.js、sundial-device.js、menu.js、welcome.js、style.css、pages.css 与本地逐字节一致。运行验证使用本地页面和 Chromium，包含移动触屏模拟；没有进行 Safari 或所有移动设备验证。本次只核查，未修改产品代码。

## 结论

报告不是全部属实。它混合了可以复现的缺陷、真实但后果被夸大的代码问题、条件性隐患和原本要求的设计。报告末尾的勾选表没有附带运行环境、测试脚本或日志，不能据此认定补丁已经通过验收。

| 编号 | 核查判断 | 证据与界限 |
| --- | --- | --- |
| 01 | 部分描述属实，严重程度和修复方向不准确 | 欢迎页没有执行旧的离场动画，这是事实；但进入实验台、联系作者均通过有效链接跳转。实测联系作者进入 contact.html。独立联系页面符合此前要求，不能称为反馈入口失效，也不应擅自恢复弹窗。 |
| 02 | 属实 | 水平、赤道日晷读数都算出 12:00，但两个读数节点的 checkVisibility() 均为 false；它们留在隐藏结构内。 |
| 03 | 正常路径未复现，属于条件性兼容隐患 | 独立页 sundialPanel 的确是 SECTION，但适配代码已设 panel.open=true。直接调用 openSundialDialog() 不抛错。只有把 open 改成 false 才会进入缺少 showModal 的分支。报告没有证明正常用户操作能触发。 |
| 04 | 冗余赋值属实，偶发崩溃未证实 | 函数末尾确有重复且无判空的赋值；但当前布局创建 uiPlaceText 后不会在正常切换中删除它。可以防御性整理，不能据此宣称已经出现偶发异常。 |
| 05 | 属实 | 实测两种说明初始都可见，切换赤道日晷后仍都可见；应跟随类型显示。文字同时出现，并不等同于位置实际重叠。 |
| 06 | 状态隔离属实，不能直接定义为缺陷 | 独立日晷属于太阳实验，只保存太阳状态。此前要求太阳、月球独立管线和状态；月球地点保持原值是这一设计的结果。月球菜单也不提供日晷入口。是否共享地点属于产品决策，报告补丁会改变现有状态隔离。 |
| 07 | 数值隐患存在，所述自然触发场景未证实 | pointermove 对 w/h 的除法确实缺少零值保护；但零尺寸或隐藏画布通常无法被用户正常命中。未复现报告所述后台加载、首帧操作造成不可恢复黑屏。可以加保护，但不应把假设写成已发生故障。 |
| 08 | 重复绘图属实，“每一帧200%/导致发热”未证实 | 对一次完整 render() 计数，drawSolarSky 被调用两次。但动画调度中有只调用 drawMotionCanvases 的分支，隐藏画布也由 canPaint 跳过。不能推导每帧所有画布都双绘，更没有低端设备帧率或功耗测量。删除冗余绘图还需验证切换视图时的可见性更新顺序。 |
| 09 | 隐藏旧结构属实，属于维护债务 | 独立页面保留旧欢迎结构。不是直接影响地理事实的功能故障；改善 LCP 的幅度没有测量。删除前需检查初始化脚本仍依赖的节点。 |
| 10 | 条件性缺陷属实 | 人为设 place.selectedIndex=-1 后，updateMenu 确实抛出读取 text 的异常。当前正常地点选择未复现；保存状态只检查字段类型，对无效 place 字符串缺少完整校验。应做状态校验与安全回退，不能描述为一般用户必然遇到。 |
| 11 | 属实 | 在图解页点击 eventsLink 后 hash 为 #riseSetPanel，但 uiWorkspace.selected 仍是 contextPanel，方位盘不可见。缺少 hashchange 同步。另：顶部标签使用 replaceState，不新增历史记录，仅补 hashchange 不能让每次标签点击都可后退。 |
| 12 | 所称天体位置和日影脱节不成立 | 设置太阳逐日模式、2026-03-20、time=1440、dec=-99 后运行 render()，日期推进到 03-21、时间归零，dec 已更新为 sunContext().dec，值约 0.02647990793°。updateUI() 会刷新它；真实日期模式 bodyPosition 按日期计算星历，日影使用同一位置，不依赖旧 dec。跨日辅助函数短暂留下旧缓存不等于最终物理图形错误。 |
| 13 | 当前版本不成立 | 390×667 视口实测 uiParametersButton 的 computed display 为 none，checkVisibility 为 false。当前没有报告所称可点击的黄色悬浮按钮。参数栏独立滚动，强行 scrollIntoView 还可能破坏图形与时间条同时可见的要求。 |
| 14 | 属实，设备范围应收窄 | dome 画布 touch-action 为 pan-y。Chromium 移动触屏模拟中，真实纵向触摸产生 pointerdown、pointermove、pointercancel，拖动被取消。可确认手势冲突；没有验证“所有触屏设备”。 |
| 15 | 暂未证实 | 0ms 清理标记存在潜在时序疑问，但 Chromium 实测12次日晷拖动释放，释放前后的时间全部一致，未出现吸附跳变。不能凭猜测宣布高帧率设备已有此故障。拟议补丁也需验证拖动未产生 click 时标记是否残留并吞掉下一次正常点击。 |

## 应优先处理的内容

1. 补回日晷实际读数，并让读数、安装说明跟随日晷类型切换。
2. 同步图解链接、URL hash 与当前显示；单独决定是否为标签切换建立浏览器历史记录。
3. 修复三维日行迹画布的触屏手势冲突。
4. 整理完整更新的重复绘图，验证切换视图首帧，再考虑性能量测。
5. 加强地点恢复校验与必要的数值保护。

不要照单应用全部补丁：恢复联系弹窗、强制同步太阳与月球地点、强行滚动整个页面，都可能与已经确定的需求冲突。本核查也不等同于对项目全部天文或地理计算的重新认证。
